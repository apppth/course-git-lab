# Заметки по Git

## Git

1. Git хранит историю у меня на компьютере в папке `.git`. GitHub это просто сервер, куда я отправляю копию.
2. У файла три состояния: изменён на диске, добавлен в индекс (`git add`), зафиксирован (`git commit`). `git status` показывает, где что лежит.
3. Коммит это снимок проекта плюс сообщение. В сообщении пишу, зачем правка, а не какие файлы трогал.
4. Ветка это ярлык на коммит. HEAD показывает, где я сейчас.
5. `git fetch` только скачивает изменения, а `git pull` скачивает и сразу вливает в текущую ветку.
6. Конфликт бывает, когда в двух ветках поменяли одни и те же строки. Убираю маркеры, оставляю нужный текст, `git add`, `git commit`.
7. `.env` и ключи в репозиторий не кладу. Если секрет уже улетел на сервер, удаление файла не поможет, ключ надо менять.

## Git Flow

1. `main` это то, что уже вышло. Туда ничего не пушат руками, только релизы и хотфиксы.
2. `develop` это сборка следующей версии. Все фичи сначала попадают сюда.
3. `feature/*` делаю от свежего `develop` и через PR возвращаю в `develop`. Одна задача, одна ветка.
4. `release/*` отделяют от `develop`, когда набор фич готов. Там только багфиксы и номер версии, потом вливают в `main` и обратно в `develop`.
5. `hotfix/*` нужен, когда на проде что-то сломалось срочно. Ветку берут от `main`, фикс вливают в `main` и в `develop`, иначе баг вернётся в следующем релизе.
6. PR фичи в `main` открывать нельзя. Если так вышло, меняю base на `develop`.
